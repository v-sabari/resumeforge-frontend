# ResumeForge AI — Frontend

Production frontend for **ResumeForge AI**, a SaaS platform for building ATS-optimized resumes with AI assistance.

Live app: [resumeforgeai.site](https://www.resumeforgeai.site)

## Tech Stack

| Layer       | Tech                                   |
|-------------|-----------------------------------------|
| Framework   | React 18.3 + Vite 5.4                   |
| Routing     | React Router 6.30                       |
| State       | Zustand 4.5                             |
| HTTP        | Axios 1.8                               |
| Styling     | Tailwind CSS 3.4                        |
| PDF export  | Puppeteer (`@sparticuz/chromium-min`) via a Vercel serverless function |
| Payments    | Razorpay                                |
| Hosting     | Vercel (frontend + `/api` function)     |

## Features

- **Auth** — registration with email OTP verification, login, password reset, JWT-based protected routes
- **Resume builder** — step-by-step editor, live preview, multiple ATS templates, section-based editing, auto-save
- **AI tools** — content rewriting, bullet point improvement, summary generation, ATS scoring, cover letter generation, LinkedIn optimization, grammar check
- **Export** — PDF (server-rendered), DOCX, ATS-safe TXT, with free-tier daily limits
- **Premium** — Razorpay checkout, unlimited exports, advanced templates
- **Referrals** — referral codes, tracking, rewards
- **Admin panel** — user management, payment tracking, analytics

## Getting Started

### Prerequisites

- Node.js 18+
- npm (or yarn / pnpm)

### Installation

```bash
git clone <repo-url>
cd resumeforge-ai-frontend
npm install
```

### Environment Variables

Copy the example file and fill in your own values:

```bash
cp .env.example .env
```

| Variable                     | Description                                   |
|-------------------------------|-----------------------------------------------|
| `VITE_API_BASE_URL`           | Base URL of the backend API                    |
| `VITE_APP_NAME`                | Display name of the app                        |
| `VITE_RAZORPAY_KEY_ID`         | Razorpay **public** key ID (never the secret)  |
| `VITE_RAZORPAY_LINK`           | Razorpay payment link                          |
| `VITE_GA4_ID`                  | Google Analytics 4 measurement ID              |
| `VITE_ADSENSE_CLIENT`          | Google AdSense client ID                       |
| `VITE_ADSENSE_SLOT_CONTENT`    | AdSense ad slot ID                             |

### Development

```bash
npm run dev
```

Runs at `http://localhost:5173`.

### Build

```bash
npm run build
```

This runs three steps in order:
1. `build:pdf-css` — compiles `src/pdf-input.css` into `api/_pdf-compiled.css` with a dedicated Tailwind config for the PDF renderer
2. `build:api` — bundles `src/pdf/renderPdfHandler.jsx` into `api/render-pdf.js` (the Vercel serverless function)
3. Vite production build of the client app into `dist/`

Use `npm run build:csr` if you only need the client bundle without touching the API function.

### Lint

```bash
npm run lint
```

### Preview a production build

```bash
npm run preview
```

## Deployment

Deployed on **Vercel**:

- Build command: `npm run build`
- Output directory: `dist`
- `vercel.json` proxies `/api/*` to the backend and rewrites all non-API routes to `index.html` for client-side routing
- Set all `VITE_*` environment variables in the Vercel project settings

## Security

- No secrets are committed — see `.env.example` for the variables you need to supply yourself
- JWT tokens are handled client-side; only the Razorpay **public** key ID is exposed to the frontend
- See [SECURITY.md](./SECURITY.md) for how to report a vulnerability
